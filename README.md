Повнофункціональна веб-орієнтована інформаційна система для автоматизації операційних процесів спортивного комплексу (на базі конфігурації СК «Олімп»). Система об'єднує планування тренувального розкладу з багатокритеріальним контролем колізій, балансування навантаження тренерського штабу, предиктивний облік зносу спортивного інвентарю та рольове розмежування доступу.

---

## 🚀 Ключові можливості та бізнес-алгоритми

### 1. Інтелектуальний розклад та контроль колізій (`ScheduleService`)
* **4-рівнева валідація часових слотів:** при створенні або редагуванні тренування система математично перевіряє перетин інтервалів `(Start_A < End_B) && (End_A > Start_B)` одночасно за зайнятістю тренера, доступністю локації (залу/басейну), статусом прикріпленого обладнання та входженням у робочі години комплексу (`OutsideWorkingHours`).
* **Клонування тижневого розкладу (`POST /api/schedule/clone-week`):** масове копіювання занять на наступний тиждень (`+7 днів`) в один клік із автоматичним пропуском конфліктних слотів та формуванням детального звіту причин пропуску.
* **Інтерактивна сітка (`ScheduleGrid`):** створення тренувань кліком по вільному вікну часу, живий індикатор поточного часу та експорт тижневого розкладу у стандартний формат **iCalendar (`.ics`)** для Google/Apple Calendar.

### 2. Управління персоналом та балансування навантаження (`TrainerService`)
* **Контроль перевантаження:** автоматичний розрахунок тижневих годин тренера відносно індивідуального або системного ліміту (`MaxWeeklyHours`) з візуальною індикацією статусів навантаження.
* **Автоматичний підбір тренера (`AutoAssign`):** евристичний алгоритм пошуку оптимального фахівця за профільною спеціалізацією (`SpecializationType`) та мінімальним поточним відсотком завантаженості.

### 3. Предиктивний облік інвентарю та Канбан-дошка ТО (`EquipmentService` & `MaintenanceService`)
* **Автоматична генерація заявок на ТО:** при внесенні напрацьованих мотогодин (`add-usage-hours`) система порівнює поточний знос із порогом `WarningWearPercentage` із `SystemSettings` та автоматично створює тікет у Канбан-дошці з дедуплікацією активних заявок.
* **Життєвий цикл обслуговування:** відстеження заявок за статусами (`Open` → `InProgress` → `Resolved`) із блокуванням призначення несправного інвентарю на тренування.

### 4. Аналітика, конфігурація та звітність (`SettingsService` & `ReportService`)
* **Централізовані параметри комплексу:** динамічне керування назвою закладу, робочими годинами (`08:00–22:00`), дефолтним лімітом годин тренерів та порогами зносу обладнання.
* **Експорт звітів у CSV:** генерація «Табеля завантаженості персоналу» та «Журналу ТО та зносу інвентарю» з кодуванням **UTF-8 BOM** та роздільником `;` для миттєвого відкриття в Microsoft Excel без спотворення кирилиці.

### 5. Дизайн-система Swiss Industrial Crimson & UX
* **Дві теми оформлення:** висококонтрастна світла **Light Industrial** та темна **Carbon Dark** (`#09090b`) з акцентною палітрою **Crimson (`rose-600`)** та технічною типографікою **JetBrains Mono**.
* **Command Palette (`Ctrl + K`):** швидка навігація з клавіатури, миттєвий пошук тренерів, інвентарю та перемикання параметрів інтерфейсу (тема, щільність таблиць `Compact / Comfortable`).

## 🔐 Рольова модель доступу (RBAC) та демо-акаунти

Автентифікація побудована на базі **JWT Bearer** із підтримкою входу як за `Email`, так і за `Username`. На екрані входу доступний блок швидкого входу в 1 клік:

| Роль | Email | Логін | Пароль | Доступний функціонал та обмеження |
| :--- | :--- | :--- | :--- | :--- |
| **Admin** (Адміністратор) | `admin@sport.ua` | `admin` | `admin123` | Повний доступ: операційний дашборд, CRUD персоналу й інвентарю, управління всім розкладом, налаштування комплексу, експорт звітів. |
| **Trainer** (Тренер) | `trainer@sport.ua` | `trainer` | `trainer123` | Персональний «Мій дашборд» із лімітом власних годин, керування лише власними слотами розкладу, створення заявок про поломку інвентарю. |
| **Technician** (Технік) | `tech@sport.ua` | `tech` | `tech123` | Прямий старт із розділу «Інвентар і ТО», Канбан-дошка ремонтів, внесення напрацьованих годин, перегляд розкладу (`Read-Only`), експорт журналу зносу. |

## 🏗️ Архітектура проєкту

```text
SportsComplexSystem/
├── SportsComplexSystem.API/          # ASP.NET Core 8.0 Web API
│   ├── Controllers/                  # 9 REST-контролерів із матрицею [Authorize(Roles = ...)]
│   ├── DTOs/                         # Ізольовані контракти запитів/відповідей (Zero Entity Leakage)
│   ├── Data/                         # AppDbContext (EF Core) та DbInitializer (початковий сідінг)
│   ├── Migrations/                   # Міграції схеми PostgreSQL
│   ├── Models/                       # Доменні сутності та Enums
│   └── Services/                     # Бізнес-логіка (Interfaces + реалізації)
└── client/                           # React + TypeScript + Vite SPA
    └── src/
        ├── api/                      # Модульний HTTP-клієнт (Axios + JWT-інтерсептори)
        ├── components/               # Common UI, Layout (CommandPalette, Sidebar), Domain-віджети
        ├── context/                  # AuthContext (сесії, RBAC) та PreferencesContext (тема, щільність)
        ├── hooks/                    # Кастомні React-хуки для роботи з даними
        ├── pages/                    # Login, Dashboard, Staff, Schedule, Inventory, Settings
        ├── types/                    # Сувора типізація TypeScript
        └── utils/                    # Перевірка перетину часу, генерація .ics, форматери
```

## ⚙️ Локальний запуск

### Вимоги
* [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
* [Node.js 20+](https://nodejs.org/)
* [PostgreSQL 15+](https://www.postgresql.org/)

### 1. Запуск Backend API (`http://localhost:5054`)
```bash
cd SportsComplexSystem.API
dotnet ef database update
dotnet run
```
> При першому запуску `DbInitializer` автоматично створить налаштування комплексу, 3 демо-акаунти, тренерський склад, локації, обладнання та розклад занять. Swagger UI доступний за адресою `http://localhost:5054/swagger`.

### 2. Запуск Frontend (`http://localhost:5209`)
```bash
cd client
npm install
npm run dev
```
Після запуску відкрийте у браузері `http://localhost:5209`.
