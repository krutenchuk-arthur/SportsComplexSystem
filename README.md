Повнофункціональна корпоративна інформаційна система класу ERP для автоматизації операційних, кадрових, технічних та фінансових процесів спортивного комплексу (на базі конфігурації СК «Олімп»). Система поєднує планування тренувального розкладу з багатокритеріальним контролем колізій, балансування навантаження і розрахунок фонду оплати праці персоналу, предиктивний облік зносу інвентарю з QR-паспортами, журнал аудиту дій та оновлення даних у реальному часі.

---

## 🚀 Ключові можливості та бізнес-алгоритми

### 1. Інтелектуальний розклад, місткість залів та контроль колізій (`ScheduleService`)
* **4-рівнева валідація часових слотів:** при створенні або редагуванні тренування система математично перевіряє перетин часових інтервалів $(Start_A < End_B) \land (End_A > Start_B)$ одночасно за зайнятістю тренера, доступністю локації (залу/басейну), технічним станом прикріпленого обладнання та входженням у робочі години комплексу (`OutsideWorkingHours`).
* **Контроль місткості локацій (`CapacityExceeded`):** перевірка ліміту учасників (`BookedCount <= Location.MaxCapacity`) із візуальною індикацією заповненості (`4/25`, `12/12 ЗАПОВНЕНО`) безпосередньо на картках занять.
* **Клонування тижневого розкладу (`POST /api/schedule/clone-week`):** масове перенесення занять на наступний тиждень (`+7 днів`) в один клік із автоматичним пропуском конфліктних слотів і деталізацією причин пропуску.
* **Інтерактивна сітка (`ScheduleGrid`):** створення тренувань кліком по вільному вікну часу, живий індикатор поточного часу та експорт розкладу у стандарт **iCalendar (`.ics`)** для Google/Apple Calendar.

### 2. Управління персоналом, балансування годин та ФОП (`TrainerService`)
* **Контроль перевантаження:** автоматичний підрахунок тижневих годин тренера відносно індивідуального або системного ліміту (`MaxWeeklyHours`) з кольоровою індикацією навантаження.
* **Евристичний автопідбір (`AutoAssign`):** пошук оптимального тренера за профільною спеціалізацією (`SpecializationType`) та мінімальним поточним відсотком завантаженості.
* **Фінансовий розрахунок ФОП:** облік індивідуальних погодинних ставок (`HourlyRate`, `₴/год`) та автоматичний прогноз тижневого фонду оплати праці на операційному дашборді.

### 3. Предиктивний облік інвентарю, QR-паспорти та Канбан ТО (`EquipmentService` & `MaintenanceService`)
* **Автоматична генерація заявок на ТО:** при внесенні напрацьованих мотогодин (`add-usage-hours`) система порівнює поточний знос із порогом `WarningWearPercentage` із `SystemSettings` та автоматично створює заявку в Канбан-дошці з дедуплікацією активних тікетів.
* **Канбан-дошка ремонтів та облік витрат:** управління життєвим циклом заявок (`Open` → `InProgress` → `Resolved`) із фіксацією вартості запчастин і робіт (`RepairCost`, `₴`) та підрахунком загального бюджету обслуговування.
* **QR-паспорти обладнання (`EquipmentPassportModal`):** генерація QR-етикеток (`qrcode.react`) із прямими deep-link посиланнями (`/?equipmentId=<id>`), переглядом повної історії ремонтів та швидкими діями в один дотик для мобільної роботи техніка в залі.

### 4. Журнал аудиту (`AuditService`) та синхронізація в реальному часі (`ComplexHub`)
* **Журнал аудиту дій (`GET /api/audit`):** фіксація критичних операцій у системі (створення/видалення слотів, клонування тижня, зміна параметрів комплексу, створення/закриття заявок ТО) із зазначенням користувача, його ролі та точного часу (доступно виключно для `Admin`).
* **Real-Time через ASP.NET Core SignalR (`/hubs/complex`):** миттєве оновлення дашборду, Канбан-дошки ремонтів та стрічки аудиту між сесіями різних користувачів без перезавантаження сторінки, з індикатором стану підключення `LIVE` у верхній панелі.

### 5. Конфігурація комплексу та звітність (`SettingsService` & `ReportService`)
* **Централізовані налаштування:** керування назвою закладу, робочими годинами (`08:00–22:00`), дефолтним лімітом годин тренерів і порогами зносу обладнання.
* **Експорт звітів у CSV:** генерація «Табеля завантаженості та нарахувань персоналу» (з розрахунком суми `Години × Ставка`) і «Журналу ТО та витрат на інвентар» у кодуванні **UTF-8 BOM** із роздільником `;` для коректного відкриття в Microsoft Excel.

### 6. Дизайн-система Swiss Industrial Crimson & Адаптивний UX
* **Дві теми оформлення:** контрастна світла **Light Industrial** та темна **Carbon Dark** (`#09090b`) з акцентною палітрою **Crimson (`rose-600`)** і технічною типографікою **JetBrains Mono**.
* **Адаптивність під усі екрани (`360px` – `2560px`):** мобільне меню-шторка (`< 1024px`), згортання бічної панелі на десктопі (`scs.sidebarCollapsed`), перемикач щільності таблиць (`Compact / Comfortable`) та пропорційне масштабування `rem` для моніторів `2K / 4K`.
* **Command Palette (`Ctrl + K`):** швидка навігація з клавіатури, пошук тренерів, обладнання та перемикання налаштувань інтерфейсу.

## 🔐 Рольова модель доступу (RBAC) та демо-акаунти

Автентифікація побудована на базі **JWT Bearer** із підтримкою входу за `Email` або `Username`. На сторінці входу доступний блок швидкого демо-входу в 1 клік:

| Роль | Email | Логін | Пароль | Доступний функціонал та обмеження |
| :--- | :--- | :--- | :--- | :--- |
| **Admin** (Адміністратор) | `admin@sport.ua` | `admin` | `admin123` | Повний доступ: операційний та фінансовий дашборд, CRUD персоналу й інвентарю, управління всім розкладом, журнал аудиту, налаштування комплексу, експорт звітів. |
| **Trainer** (Тренер) | `trainer@sport.ua` | `trainer` | `trainer123` | Персональний «Мій дашборд» із лімітом власних годин, керування лише власними слотами розкладу, створення заявок про поломку інвентарю. |
| **Technician** (Технік) | `tech@sport.ua` | `tech` | `tech123` | Прямий старт із розділу «Інвентар і ТО», Канбан-дошка ремонтів, QR-паспорти, внесення мотогодин, перегляд розкладу (`Read-Only`), експорт журналу зносу. |

## 🏗️ Архітектура проєкту

```text
SportsComplexSystem/
├── SportsComplexSystem.API/          # ASP.NET Core 8.0 Web API + SignalR
│   ├── Controllers/                  # 10 REST-контролерів із матрицею [Authorize(Roles = ...)]
│   ├── DTOs/                         # Ізольовані контракти запитів/відповідей (Zero Entity Leakage)
│   ├── Data/                         # AppDbContext (EF Core) та DbInitializer (початковий сідінг)
│   ├── Hubs/                         # ComplexHub (SignalR реального часу на /hubs/complex)
│   ├── Migrations/                   # Міграції схеми PostgreSQL
│   ├── Models/                       # Доменні сутності (включно з AuditLog) та Enums
│   └── Services/                     # Бізнес-логіка (Interfaces + реалізації)
└── client/                           # React + TypeScript + Vite SPA
    └── src/
        ├── api/                      # Модульний HTTP-клієнт (Axios + JWT-інтерсептори)
        ├── components/               # Common UI, Layout (CommandPalette, Sidebar), Domain-віджети
        ├── context/                  # AuthContext (сесії, RBAC) та PreferencesContext (тема, щільність)
        ├── hooks/                    # Кастомні React-хуки для роботи з даними
        ├── pages/                    # Login, Dashboard, Staff, Schedule, Inventory, Settings
        ├── services/                 # SignalR клієнт (realtime.ts)
        ├── types/                    # Сувора типізація TypeScript
        └── utils/                    # Перевірка перетину часу, генерація .ics, форматери
```

## ⚙️ Локальний запуск

### Вимоги
* [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
* [Node.js 20+](https://nodejs.org/)
* [PostgreSQL 15+](https://www.postgresql.org/)

### 1. Запуск Backend API (`http://localhost:5054`)
```bash
cd SportsComplexSystem.API
dotnet ef database update
dotnet run
```
> При першому запуску `DbInitializer` автоматично створить налаштування комплексу, 3 демо-акаунти, тренерський склад зі ставками, локації з місткістю, обладнання, історію ТО та розклад занять. Swagger UI доступний за адресою `http://localhost:5054/swagger`.

### 2. Запуск Frontend (`http://localhost:5209`)
```bash
cd client
npm install
npm run dev
```
Після запуску відкрийте у браузері `http://localhost:5209`.
