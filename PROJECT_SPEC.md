# Специфікація: Програмна система контролю завантаженості персоналу та ТО інвентарю спортивного комплексу

## Основні модулі та екрани (UI/UX Views)

### 1. Аналітичний Дашборд (Overview)
- KPI-картки верхнього рівня: Загальна завантаженість тренерів (%), Кількість активних тренувань сьогодні, Інвентар у роботі / На ТО, Відкриті заявки на ремонт.
- Візуальна шкала розподілу навантаження персоналу (хто перевантажений, а хто недовантажений).
- Швидкий список критичних сповіщень (наприклад: "Бігова доріжка #INV-104 перевищила ліміт 200 год — створено заявку на ТО").

### 2. Модуль Персоналу та Балансування навантаження (Staff Workload)
- Картки/таблиця тренерів: ПІБ, Спеціалізація (Силовий тренінг, Кардіо, Кроссфіт, Плавання, Йога), Ліміт годин на тиждень (`MaxWeeklyHours`, стандарт 40 год), Фактично призначені години (`AssignedHours`).
- Індикатор коефіцієнта завантаженості: $K = AssignedHours / MaxWeeklyHours$.
- Кнопка "Автопідбір вільного тренера": повертає найбільш розвантаженого тренера потрібної спеціалізації без колізій у розкладі.

### 3. Диспетчер Розкладу з контролем колізій (Schedule Dispatcher)
- Календарна сітка (по днях/тижнях) або таймлайн по локаціях (Тренажерна зала, Зала групових занять, Кардіо-зона, Басейн).
- Модальне вікно створення заняття з перевіркою 3 правил:
  1. Чи вільна локація у вибраний інтервал $[StartTime, EndTime]$.
  2. Чи вільний обраний тренер у цей інтервал.
  3. Чи не перевищить тренер свій `MaxWeeklyHours` після додавання заняття.
  4. Чи всі вибрані для заняття одиниці інвентарю мають статус `Operational`.

### 4. Облік життєвого циклу інвентарю та Заявки на ТО (Equipment & Maintenance)
- Реєстр обладнання: Інвентарний номер (`INV-XXX`), Назва, Локація, Поточне напрацювання (`CurrentUsageHours`), Граничний поріг до ТО (`MaintenanceThresholdHours`), Статус (`Operational`, `MaintenanceRequired`, `UnderRepair`).
- Кнопка симуляції завершення тренування / додавання годин напрацювання: автоматично додає години і, якщо поріг перейдено (`CurrentUsageHours >= MaintenanceThresholdHours`), переводить тренажер у статус `MaintenanceRequired` та створює запис у таблиці `MaintenanceTickets`.
- Kanban-дошка або таблиця заявок на ТО (`Open` -> `InProgress` -> `Completed`). При закритті заявки статус тренажера повертається в `Operational`, а лічильник годин після ТО скидається на `0`.
